# Gate pré-C08 — pendências antes da UX do START

**Data:** 27/09/2026  
**Estado:** EM TRATAMENTO

## Onde o projeto parou

O C07 foi concluído tecnicamente e o C08 estava pronto para começar. A execução foi interrompida **antes de criar a UX ou o backend START**.

O motivo foi evitar que o START nascesse dependendo de quatro informações de negócio ainda sem fonte suficiente:

| Issue | Lacuna | Risco se avançasse sem tratar |
|---|---|---|
| GI-SAFRA-001 | criticidade nominal | UI inventar CRITICAL/HIGH/MODERATE ou comunicação executiva errada |
| GI-SAFRA-002 | thresholds 2/4/10/11 | automação disparar com número inventado |
| GI-SAFRA-003 | mínimo curva A cenário 9 | falso alerta de ruptura |
| GI-SAFRA-009 | SLAs textuais | relógio começar/terminar em evento inferido |

## Princípio da correção

Resolver o comportamento do MVP **sem fabricar o dado ausente**.

A correção deve distinguir:
- regra de negócio que existe;
- dado de configuração que não existe;
- funcionalidade que fica manual;
- funcionalidade que fica não mensurável;
- evolução futura que exige nova scenario_version.

## Condição para liberar C08

C08 será liberado quando:
- criticidade ausente tiver comportamento explícito;
- thresholds ausentes não forem requisito de START;
- cenário 9 puder operar manualmente sem falsa automação;
- política de estruturação dos SLAs textuais estiver formalizada.

Depois disso:
`SAFRA-C08.1 — contrato transacional e autorização do START`.
