## SAFRA-C07.1 — Não salvar minutos como fonte primária

### Evidência

- não existem colunas persistidas de `minutes`, `duration`, `elapsed` ou `remaining` como fonte de verdade;
- `elapsed_seconds` e `remaining_seconds` são saídas derivadas da engine;
- minutos podem existir somente como unidade declarativa do alvo (`target_unit='MINUTE'`), nunca como duração operacional persistida.

Contrato:

```text
PRIMARY_DURATION_SOURCE = TIMESTAMPS
PERSISTED_DURATION_MINUTES = FORBIDDEN
DERIVED_DURATION_UNIT = SECONDS
```

Resultado: **PASS**.

## SAFRA-C07.2 — Salvar timestamps e definição do SLA

### Evidência

A definição estruturada em `scenario_slas` exige:

```text
start_event
end_event
target_value
target_unit
```

Todos são NOT NULL.

Fontes temporais operacionais:
- `treatment_events.occurred_at` = `timestamptz`;
- `treatments.opened_at` = `timestamptz`;
- `treatments.closed_at` = `timestamptz`;
- `treatments.cancelled_at` = `timestamptz`.

A duração é recalculável a partir dos eventos e da definição, sem depender de valor de minutos persistido.

Resultado: **PASS**.

## SAFRA-C07.3 — Sinalizar explicitamente quando ainda não mensurável

### Evidência

Casos validados:

```text
START ausente
=> NOT_MEASURABLE / START_EVENT_MISSING

target estruturado ausente
=> NOT_MEASURABLE / STRUCTURED_TARGET_MISSING

as_of ausente
=> NOT_MEASURABLE / AS_OF_MISSING

relógio antes do START
=> NOT_MEASURABLE / CLOCK_BEFORE_START
```

O sistema não inventa timestamp nem aplica fallback silencioso.

Resultado: **PASS**.

## SAFRA-C07.5 — Impedir relógio/duração negativa

### Evidência

- `remaining_seconds` é limitado a zero após breach;
- `as_of < START` não gera duração negativa: retorna `NOT_MEASURABLE / CLOCK_BEFORE_START`;
- END/CANCEL antes do START são rejeitados;
- a matriz adversarial confirmou relógio não-negativo.

Resultado: **PASS**.

## SAFRA-C07.6 — Tolerância temporal somente quando documentada

### Estado atual

O sistema possui **zero tolerância implícita**:

```text
as_of = deadline
=> ON_TRACK

as_of = deadline + 1 ms
=> BREACHED
```

Também não existem no modelo:
- `tolerance_value`;
- `tolerance_unit`;
- `tolerance_reason`;
- `tolerance_documentation`;
- campos equivalentes de grace/buffer.

A busca no repositório não encontrou implementação de `tolerance`, `grace` ou `buffer`.

### Diagnóstico

A ação completa foi implementada.

Contrato persistido:

```text
tolerance_value
tolerance_unit
tolerance_documentation
```

Regras:
- sem tolerância => os três campos permanecem NULL e o comportamento anterior é preservado;
- com tolerância => `tolerance_value > 0`;
- `tolerance_unit` aceita somente `MINUTE`, `HOUR` ou `DAY`;
- `tolerance_documentation` é obrigatória e não pode ser vazia;
- configuração parcial ou sem documentação => `NOT_MEASURABLE / TOLERANCE_CONFIGURATION_INVALID`;
- a tolerância altera somente o deadline efetivo;
- START, END e duração real observada não são deslocados;
- tolerância implícita continua proibida.

Resultado: **PASS**.
